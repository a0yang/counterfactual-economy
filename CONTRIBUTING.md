# Contributing to Counterfactual Economy

Thank you for considering contributing.

This project is intentionally cross-disciplinary. Good contributions may be code, economic models, datasets, historical case studies, tests, documentation, visualizations or constructive criticism.

## Before opening an issue

Search existing Issues and Discussions first. A duplicate idea can usually be improved by joining an existing thread.

## Good first contributions

Examples:

- document one historical dataset and its license;
- add tests for an accounting identity;
- implement one small policy rule;
- reproduce one published empirical relationship;
- improve the README or documentation;
- build a simple visualization;
- challenge an assumption with a documented counterexample.

## Economic-model contributions

Please describe:

1. the mechanism;
2. the variables;
3. equations or decision rules;
4. parameter meanings and units;
5. source literature or empirical justification;
6. calibration method;
7. known limitations;
8. tests or historical episodes used for validation.

Avoid describing a model only as “Keynesian”, “monetarist”, “Austrian”, etc. Name the concrete mechanism being implemented.

## Data contributions

Please provide:

- source;
- series identifiers;
- frequency;
- units;
- observation and release/vintage conventions;
- license;
- preprocessing steps;
- known data breaks or limitations.

## Pull requests

A pull request should explain:

- what changed;
- why it changed;
- how it was tested;
- whether results changed;
- whether documentation needs updating.

Keep pull requests focused. A small, understandable change is easier to review than a large mixed patch.

## Reproducibility

Where a simulation result is discussed, provide:

- model version;
- data version;
- parameter configuration;
- random seed when relevant;
- experiment name or scenario identifier.

## Scientific disagreement

Disagreement is expected and useful. Challenge assumptions with evidence, alternative models and reproducible experiments rather than appeals to authority.

## Governance

During the early stage, the project is community-driven but founder-initiated. As the contributor base grows, governance can evolve toward maintainers, model reviewers and domain-specific working groups.
