# Community launch plan

The first objective is not to attract thousands of followers. It is to find a small group of technically and academically strong people who are willing to test the idea.

## Stage 1 — Publish the repository

Publish the repository with:

- English README;
- Chinese README;
- project vision;
- architecture proposal;
- research agenda;
- 2008 challenge;
- contribution rules.

## Stage 2 — Ask for criticism, not volunteers

A first public message should lead with a concrete research problem:

> Can an open-source economic simulation, using only information available before 2008, identify the buildup of financial vulnerability and test alternative mortgage and banking policies?

This is more actionable than “help me build a game.”

## Stage 3 — Recruit by discipline

Look separately for:

1. computational economists;
2. scientific software engineers;
3. data engineers;
4. quantitative / financial researchers;
5. visualization or Godot developers.

Do not require one person to have all five skill sets.

## Stage 4 — Publish a small result

The first public milestone should ideally be a reproducible notebook or report, even if the model performs poorly.

A credible failure is more valuable than an impressive but opaque demo.

## Stage 5 — Invite competing models

Once the baseline challenge exists, explicitly invite alternative models to run against the same data and evaluation protocol.

The project should reward explanation, reproducibility and robustness rather than a single “winner.”

## Suggested opening post

> We are starting an open-source project to explore counterfactual economic history.
>
> The idea is to build a transparent simulation environment combining historical data, economic mechanisms, agents, financial networks and policy rules.
>
> The first scientific challenge is deliberately small: use only information available before 2008 to investigate whether a simulation can detect rising financial vulnerability in the U.S. economy and test whether alternative policies would materially change the outcome distribution.
>
> The long-term goal is a platform that can be both a 2D historical economic simulation game and a reproducible research environment.
>
> We are especially interested in people working in computational economics, macro-finance, ABM/SFC modeling, scientific computing and economic data.
>
> Critical feedback is welcome. The project is intentionally not claiming that one model can predict the future.
